## How a task becomes a brief (the compile rule — the orchestrator follows it verbatim)

One task → one brief `T0NN.md` in the run's `briefs/`, per `~/.agents/skills/splitbrief/references/brief-format.md`:
1. **Frontmatter:** `id` (in emission order within the run), `title` = the task's title, `action` = the task's `(create|modify)` (a `rewrite` task is `modify`), `file` = the task's file (project-relative from `website/`… the splitbrief run's project root is `website/` — run it from there so `file:` paths are `src/…`, `tests/…`, `index.html`), `depends_on` = the previous brief of the run (briefs are a chain). **Path form for drift and G-tree:** `git status --porcelain` prints repo-root-relative paths (`website/src/styles/lower.css`) even when run from `website/` (checked 2026-09-09), so the drift check and G-tree compare git's paths against the brief's `file` and its approved paths with `website/` prefixed; `baseline-tree.txt` holds the same root-relative form.
2. **Description** = the task's **After** contract, followed by the **Quote** slices copied VERBATIM from `website/DESIGN.md` (the named subsection's named rows / paragraphs — never the whole sheet) and, when named, the comp's CSS/markup lines from `RUN/comps/lower-page.html`.
3. **Signature / Type Definitions** = the task's **Calls** entries, copied verbatim from the named files (exports, types).
4. **Current Code** = the file verbatim when ≤ 300 lines, else the enclosing region with `(excerpt: lines a–b of n)`; a `create` task quotes the neighbouring file it mirrors under **Pattern**.
5. **Implementation Steps** = the task's **Steps** (3–5).
6. **Tests** = the task's **Accept** lines as bullets (each a command or a measurement), then `**Validation commands:**` = G-type, G-lint, G-test verbatim.
7. **Scope**: In bounds = the file; Out of bounds = the task's **Out** list + "every other file"; Approved out of bounds = the task's **Approved** list (paths only), when any.
8. **Escalation** = the task's **Stop** list.
9. **Evidence** = "the gate output recorded by the orchestrator; the Accept commands' output; the changed-file list".
10. **Constraints** = the Executor context's Conventions bullets verbatim + the four closing constraints (no new functions, no new features, no new packages, no git add/commit/stash/.bak).
11. **Preamble (implementer-prompt.md §1):** the generated line `Use ESM imports with .js extensions` is rendered as `Use extensionless ESM imports (moduleResolution: bundler — the Vite convention)`, the project's own convention, so the preamble and the Constraints agree; the closing line and the retry framings are used as generated.
A brief never contains another task's slice, the spec, the critique files or the whole sheet.
