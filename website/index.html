02Before any code

ONE FILE.ONE BRIEF.NOTHING ELSE.

BRIEFS
CONTRACTS
CONTEXT
CLARITY

The planner writes one brief per file. The implementer sees only its own brief — not the spec, not the plan, not the other tasks — and runs it in fresh context, with no memory of the last one.

ONE FILE.
ONE BRIEF.
NOTHING ELSE.

A brief that fails its checks never reaches an implementer. splitbrief validates every brief upfront — scope, file, dependencies, signature — and stops at the first domain or contract error.

CLEAR INPUTS.
SAFER OUTPUTS.

03After every task

VALIDATE.RETRY.ESCALATE.KEEP THE EVIDENCE.

Correctness is not the implementer's to judge. After every task splitbrief runs typecheck, lint and test in your project and stops at the first failure.

A failed task retries with the error attached, up to three times. Then it escalates: a mid‑tier model if configured, a hint from the planner, or a human review. Every run stores logs, results and evidence.
