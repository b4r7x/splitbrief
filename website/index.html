three when another lab reviews. The stronger one plans and reviews, the cheaper one executes — and splitbrief holds the contract between them.

MIX THE LABS.
ONE SHARED BRIEF.

BEFORE ANY CODE

ONE FILE.
ONE BRIEF.
NOTHING ELSE.

The planner writes one brief per file. The implementer sees only its own brief — not the spec, not the plan, not the other tasks — and runs it in fresh context, with no memory of the last one.

A brief that fails its checks never reaches an implementer. It reads CONTRACT BLOCKED until you retry, edit, or reject.

// YOU DESCRIBE
THE GOAL.
SPLITBRIEF HOLDS
THE REST.

From research to Task Briefs to review, the stronger tool thinks and the cheaper one types. splitbrief validates every task — typecheck, lint, test — retries, escalates, and keeps the evidence.

AFTER EVERY TASK

NOT ITS OWN JUDGE.

  1. 01TYPECHECK → LINT → TEST
  2. 02RETRY ×3 WITH THE ERROR
  3. 03MID-TIER MODEL
  4. 04A HINT FROM THE PLANNER
  5. 05THE PLANNER WRITES IT°
  6. 06YOU DECIDEretry · a bigger worker · skip · pause · abort

Correctness is not the implementer's to judge. After every task splitbrief runs typecheck, lint and test in your project and stops at the first failure the task caused. A stage that was already red before the run does not count against it.

A failed task retries with the error attached, up to three times. Then it escalates: a mid‑tier model if you have one, a hint from the planner, and finally the planner writes the code itself. If that fails too, you decide.

° That last tier is the one path where the tool that wrote the code also reviews it.

AFTER THE RUN

THE EVIDENCE.
ON DISK.
IN YOUR REPO.

Every run is a session folder in your project. The state, the log, the briefs, the evidence and the review are files you can open, diff, and resume from.

.splitbrief/
├── config.yaml
├── active                     // the current session
└── sessions/
    └── 2026-04-14-add-user-auth/
        ├── state.json         // the source of truth for resume
        ├── session.jsonl      // every event and message, append-only
        ├── research.md
        ├── spec.md
        ├── plan.md
        ├── tasks.md           // every brief, one per file
        ├── evidence.json      // what was to be proved, and what was observed
        ├── review.md          // the reviewer's read
        ├── summary.json
        └── snapshots/

Early software, pre-1.0. Cost is reported per run, never promised. Two numbers will decide whether the split is worth it — first-pass rate, and how much the cross-lab review catches that validation did not. Neither is measured yet.
