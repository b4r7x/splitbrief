01 / PLANNER stronger tool

Turn a request into a plan.

Your planning tool reads the repository and works out what needs to change. SPLITBRIEF saves that context before implementation starts.

✓ Repository rules, existing code, types and tests
research.mdWhat is already here✓
spec.mdThe behavior you agree on✓
plan.mdThe order of the changes✓

You review the spec before the work moves on.

02 / TASK BRIEF the handoff

Give the next tool a complete job.

The planner compiles each change into a self-contained Task Brief. The implementer gets everything it needs for that task.

Scope
Files it may change. Boundaries it must keep.
Context
Code, types, signatures and ordered steps.
Checks
Acceptance criteria and validation commands.
Stop if
An assumption fails. Return to the planner.

✓ You approve the briefs before execution.

03 / IMPLEMENTER smaller tool

One brief in. A scoped change out.

SPLITBRIEF sends the approved brief to your implementation tool. It follows the instructions and changes the declared files.

PLANNERTask Brief········→IMPLEMENTERWorking changes

It receives this brief — not the full spec, the whole plan or the other tasks.

task / T001✓ ready for validation

04 / VALIDATION SPLITBRIEF

Check the work. Keep the evidence.

After implementation, SPLITBRIEF runs the configured checks in your project. A failure goes back with the brief for another attempt.

typecheck✓ passed
lint✓ passed
tests× acceptance check failed
↳

Retry with the failure attached.Escalate to the stronger tool if retries run out.

typecheck / lint / tests✓ passed on retry

05 / REVIEW stronger tool

Bring the planner back to the diff.

Passing checks is one part of the job. The reviewer reads the finished changes against the spec and the briefs.

✓
The requested behavior is there.Compare the result with the spec.
✓
The agreed scope is intact.Check the diff against the briefs.
✓
The evidence supports the result.Inspect the validation output.

The planner is the reviewer by default. You can configure a separate one.

06 / LOCAL RECORD your repository

Briefs, validation results and review stay in the local session. You can inspect the decisions and continue an unfinished run.

01 / THE SETUP

Your tools. Your roles.

Choose a stronger model for planning.
A smaller one for implementation.

.splitbrief/config.yamlexample configuration
version: 3

planner:
  kind: cli
  tool: claude-code
  model: opus

implementer:
  kind: cli
  tool: codex
  model: auto
Set each role’s model. auto uses that tool’s default.

The planner also reviews by default. The tools and models are your choice.
