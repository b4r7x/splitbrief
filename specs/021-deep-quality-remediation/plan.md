## Implementation Phases

### Phase 1: Critical Bug Fixes (User Story 1)

**Goal**: Fix the 3 critical bugs that cause data loss or crashes.

**Tasks**:
1. **Router overlay rendering** (FR-001): Change `router.tsx` to render overlays as siblings with `display="none"` on the screen `<Box>`. All 3 overlays (help, command-palette, skills) rendered conditionally alongside the screen.
2. **Input mode type safety** (FR-002): Split `resolverRef` in `use-input-mode.ts` into `reviewResolverRef` and `questionResolverRef` with proper types. `resetMode` resolves each with its type-appropriate default.
3. **CLI error handler** (FR-003): Add `.catch()` on `program.parseAsync()` in `cli.ts` that logs a friendly message and exits with code 1.

**Verification**: Open overlays during workflow (no kill), cancel during question prompt (no type error), trigger CLI error (friendly message).

### Phase 2: Type Safety (User Story 3)

**Goal**: Eliminate untyped strings and `any` casts.

**Tasks**:
4. **Typed event strings** (FR-011): Add `TuiEventType = TuiEvent['type']` to `types.ts`. Update `emit()` signature in `events.ts`.
5. **Typed frontmatter** (FR-012): Add `TaskFrontmatter` interface to `types.ts`. Update `extractFrontmatter` return type in `parser.ts`.
6. **Safe process.pid** (FR-014): Add null check in `killProcess` in `process.ts` before calling `process.kill`.
7. **Typed input mode resolvers** (FR-013): Already addressed in task 2.

### Phase 3: Dead Code Removal (User Story 4)

**Goal**: Remove all dead exports, unused actions, redundant code.

**Tasks**:
8. **Remove dead exports** (FR-015): Remove or unexport the 11 dead symbols identified in the audit.
9. **Remove dead reducer actions** (FR-016): Remove 5 unused action types and their case branches from `use-workflow.ts`.
10. **Remove miscellaneous dead code** (FR-017): Remove `diff.ts:3` redundant line, `review-view.tsx` dead scroll state, unused React imports in `home.tsx` and `summary.tsx`, dynamic imports in `cli.ts:109-111`.

### Phase 4: Duplication Elimination (User Story 2)

**Goal**: Each pattern exists in exactly one place.

**Tasks**:
11. **addUsageAndSave helper** (FR-004): Create a combined helper in `orchestrator/helpers.ts` that calls `addUsage` + `saveState`. Update all 9 call sites.
12. **Single planner instance** (FR-005): Create planner once in `runWorkflow` and pass through to task-runner escalation functions.
13. **Shared useFilterableList hook** (FR-006): Create `src/hooks/use-filterable-list.ts`. Refactor `InputBar` (slash mode), `CommandPalette`, and `SkillsPicker` to use it.
14. **Unified usage accumulation** (FR-007): Update `base.ts`, `agent-sdk.ts`, `opencode.ts` to use `accumulateUsage` from `output-parsers.ts`.
15. **Shared Claude stream handler** (FR-008): Extract common stream-json parsing from `spawnClaudePlanner` and `spawnClaudeWithStdin` into a shared handler.
16. **CLI start/resume deduplication** (FR-009, FR-010): Extract shared option builder and action logic. Add `contextLengthOverride` to resume path.

### Phase 5: File Restructuring (User Story 5)

**Goal**: No file exceeds 250 lines (excluding `templates.ts`). Each file has a single responsibility.

**Tasks**:
17. **Split cli.ts** (FR-018): Extract `runPicker` + `promptSelection` to `src/cli/picker.ts`. Extract `renderApp` to `src/cli/render.ts`.
18. **Split config.ts** (FR-019): Extract `validateConfig` and related helpers to `src/config-validation.ts`.
19. **Split formatter.ts** (FR-020): Extract `estimateTokens`, `truncateMiddle`, `computeTokenBudget` to `src/engine/spec/token-budget.ts`.

### Phase 6: Architecture Fixes (User Story 6)

**Goal**: Clean dependency graph with no layer violations.

**Tasks**:
20. **Move highlight.ts** (FR-021): Move `src/engine/highlight.ts` to `src/utils/highlight.ts`. Update imports in `diff-view.tsx`, `markdown.tsx`.
21. **Move ClarificationQuestion** (FR-022): Move type definition from `engine/question-parser.ts` to `types.ts`. Update imports.
22. **Move DEFAULT_BASES** (FR-023): Move constant to `src/types.ts` or a shared `src/constants.ts`. Update imports in `config.ts` and `providers.ts`.
23. **Standardize React imports** (FR-024): Remove bare `import React from 'react'` in files that don't reference `React` directly.

### Phase 7: React Pattern Improvements (User Story 7)

**Goal**: Optimal React patterns throughout the UI layer.

**Tasks**:
24. **Incremental sidebar tasks** (FR-025): Add `taskMap` to `useWorkflow` reducer state. Update `ADD_EVENT` case to maintain it. Remove `sidebarTasks` useMemo from `workflow.tsx`.
25. **Expand AppContext** (FR-026): Add `projectDir` and skills state to `AppContext`. Remove those props from router. Update consuming components.
26. **Standardize theme access** (FR-027): Remove `theme` prop from `InputBar`, `SlashSuggestions`, `Sidebar`, `ReviewView`. All use `useAppContext()`.
27. **Fix picker dead state** (FR-028): Handle the case where 2+ planners exist and exactly 1 model — auto-select and call `onComplete`.
28. **Stabilize useInputMode** (FR-029): Wrap returned functions in `useCallback`.
29. **Content-based list keys** (FR-030): Update `markdown.tsx` and `diff-view.tsx` to use content-derived keys instead of array indices.
30. **Reset async highlight state** (FR-031): In `HighlightedCode` and `DiffView`, reset highlighted state to `null` when `code`/`diff` props change.

## Parallelization Opportunities

Within each phase, many tasks are independent and can run as parallel agents:

- **Phase 3**: Tasks 8, 9, 10 are independent (different files)
- **Phase 4**: Tasks 11-12 (orchestrator), 13 (hooks/UI), 14 (planners), 15 (claude-code), 16 (CLI) — all independent
- **Phase 5**: Tasks 17, 18, 19 — all independent (different files)
- **Phase 6**: Tasks 20, 21, 22, 23 — all independent (different files)
- **Phase 7**: Tasks 24-25 (context/reducer), 26-27 (theme/picker), 28 (input mode), 29-30 (keys/highlight) — partially independent

**Recommended agent allocation**:
- Phase 1: 3 agents (one per critical bug)
- Phase 2: 3 agents (events, frontmatter, process.pid)
- Phase 3: 3 agents (dead exports, dead actions, misc dead code)
- Phase 4: 6 agents (one per dedup task)
- Phase 5: 3 agents (one per file split)
- Phase 6: 4 agents (one per move/fix)
- Phase 7: 5 agents (grouped by dependency)

**Total**: ~27 agent dispatches across 7 phases, with up to 6 running in parallel within a phase.

## Risk Mitigation

| Risk | Mitigation |
| ---- | ---------- |
| File splits break imports | Run `tsc --noEmit` after every split task |
| Parallel agent edits conflict | Each agent works on distinct files — no overlap |
| useFilterableList hook changes component behavior | Test each component's keyboard navigation manually |
| AppContext expansion causes re-renders | Context value should be memoized; profile if needed |
| Ink `display="none"` has edge cases | Test overlay open/close during active workflow |
| Dead export removal breaks tests | Update tests to use remaining public APIs |
