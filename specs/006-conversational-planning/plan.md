## Architecture Decisions

### 1. Question Protocol: HTML Comment Markers

Planner output embeds questions as `<!-- Q:{"id":"q1","type":"choice","text":"...","options":[...],"default":0} -->`.

**Why**: HTML comments are invisible to markdown, JSON is unambiguous, regex parsing is robust to streaming, malformed blocks silently ignored. Compatible with all planner output formats.

**Parsing**: `QuestionAccumulator` class buffers streaming text, extracts complete question markers incrementally. New questions emitted via `onQuestion` callback.

### 2. Multi-Turn Fallback Strategy

Claude Code and agent-sdk support multi-turn (session IDs / async generators). All other backends fall back to batch mode.

**Batch mode**: Planner generates spec without questions → user approves/edits/comments → planner regenerates if needed. Same flow as today, plus the new comment option.

**Conversational mode**: Planner streams research output → embeds questions → TUI pauses for user input → answers sent back in follow-up prompt within same session → planner generates spec incorporating answers.

### 3. Interactive Picker: Ink-Based Selection

Uses `@inkjs/ui`'s `Select` component for planner/implementer selection. Rendered before the split-pane TUI, replaced by the main layout once selections are made.

### 4. Shell Implementer: Parallel to Shell Planner

Mirrors `planners/shell.ts` architecture exactly: spawn command, write prompt to stdin, read stdout, parse with OutputFormat. Non-zero exit = failed attempt → retry. Exit 127 = command not found → permanent error.

### 5. Approval Enhancement: Comment Mode

Current prompt has: approve, edit, quit. New prompt adds: **comment** — user types feedback in TUI, planner regenerates artifact in same session. Implemented via TextInput overlay that resolves a Promise (same pattern as approval).

## Implementation Phases

### Phase 1: Foundation & Cleanup (US7, US8)

**Why first**: Clean codebase before adding new features. No dependencies on other phases.

1. Remove `src/orchestrator/planner.ts` backward-compat wrapper
2. Update `cli.ts` spec command to use `createPlanner(config)` via factory
3. Identify and remove dead imports/unused functions
4. Update constitution to v1.1.0 (new principles, anti-goals, pluggable architecture)
5. Sync documentation (CLAUDE.md, README.md, docs/VISION.md)

### Phase 2: Detection & Picker (US3)

**Why second**: Provides infrastructure for interactive setup. Independent of conversational planning.

1. Create `planner-detection.ts` with `detectAvailablePlanners()` and `detectAvailableImplementers()`
2. Create `tui/picker.tsx` Ink component with Select inputs
3. Update `cli.ts` start command: if no config and no overrides → show picker → save config
4. Update `cli.ts` init command: add planner detection alongside model detection
5. Tests for detection functions

### Phase 3: Shell Implementer (US6)

**Why third**: Independent feature. Can be implemented in parallel with Phase 4.

1. Add `type`, `command`, `args`, `outputFormat` fields to implementer config in `types.ts`
2. Update `config.ts` validation for new fields
3. Create `implementers/shell.ts` — subprocess implementer mirroring shell planner
4. Update `implementer.ts` to dispatch to shell or API based on `config.implementer.type`
5. Pre-start validation: check command exists on PATH
6. Tests for shell implementer

### Phase 4: Conversational Planning (US1, US2, US4, US5)

**Why fourth**: Builds on clean codebase (Phase 1) and detection (Phase 2). Largest scope.

1. Install `@inkjs/ui`, create `tui/user-input.tsx` wrapper
2. Create `question-parser.ts` with `QuestionAccumulator` and `extractQuestionsFromStream()`
3. Update `planners/types.ts`: add `onQuestion` callback to planner interface
4. Update `planners/claude-code.ts`: integrate QuestionAccumulator into stream parsing
5. Update `spec/templates.ts`: add question instruction to research prompt
6. Create `tui/question-prompt.tsx`: renders question with options/input
7. Update `tui/prompt.tsx`: add [c] comment option to approval prompt
8. Update `app.tsx`: add input mode state, question handling, comment handling
9. Update `orchestrator.ts`: add conversational flow (question loop before spec generation)
10. Update `orchestrator.ts`: add comment-regenerate flow at approval gates
11. File persistence: write clarifications to spec.md immediately on answer
12. Tests for question parser, conversational flow
