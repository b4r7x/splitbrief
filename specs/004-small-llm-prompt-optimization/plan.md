# Implementation Plan: diptych v0.2 -- Small LLM Prompt Optimization

**Branch**: `004-small-llm-prompt-optimization` | **Date**: 2026-03-25 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/004-small-llm-prompt-optimization/spec.md`

## Summary

Optimize diptych's task prompt generation so every task fits within an 8K token context window while maximizing small model comprehension. Extend the Task type with inlined type definitions and implementation steps. Add a few-shot example to the system preamble. Rewrite retry prompts to preserve full context. Add function-level code extraction for large files. Update documentation and create an LLM project skill.

## Technical Context

**Language/Version**: TypeScript 6.0, Node.js 22+ (native TypeScript stripping)
**Primary Dependencies**: ink 5.x, react 18.x, openai ^6.0.0, yaml, simple-git, commander ^14.0.0

**Testing**: `tsx --test tests/**/*.test.ts`
**Target Platform**: macOS (primary), Linux (secondary)
**Constraints**: Task prompts MUST fit in 8K tokens. 25% output reserve. No new runtime dependencies.

## Architecture

### Token Budget Flow

```
Config.contextLength (e.g., 8192)
       │
       ▼
┌──────────────────────────────┐
│  computeTokenBudget()        │
│                              │
│  outputReserve = 25%  = 2048 │
│  system + few-shot    =  500 │
│  taskBody (desc/sig/  =  600 │
│    tests/constraints)        │
│  typeDefs             =  300 │
│  implSteps            =  150 │
│  ─────────────────────────── │
│  available for code   = 4594 │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│  resolveCodeContext()        │
│                              │
│  file LOC < budget?          │
│  YES → whole-file            │
│  NO  → function-level        │
│        (imports + target fn  │
│         + 5 lines context)   │
│  STILL NO → truncate middle  │
│  STILL NO → error            │
└──────────────────────────────┘
```

### Function-Level Extraction

```
src/some-module.ts (400 LOC)
┌─────────────────────────────┐
│ import { ... } from '...'   │ ← extracted as imports
│ import { ... } from '...'   │
│                              │
│ export function helperA() {  │ ← listed as "other export"
│   ...                        │
│ }                            │
│                              │
│ // 5 lines before           │ ← included
│ export function targetFn() { │ ← TARGET (matched by name)
│   ...                        │
│ }                            │
│ // 5 lines after            │ ← included
│                              │
│ export function helperB() {  │ ← listed as "other export"
│   ...                        │
│ }                            │
└─────────────────────────────┘

Extracted prompt section:
  imports (full)
  + targetFn with context (5+5 lines)
  + list of other exports (names only)
```

### Modified Prompt Assembly

```
formatTaskPrompt(task, context, contextLength)
       │
       ├── buildSystemPreamble()           // rules + few-shot example (~500 tok)
       │
       ├── buildTaskBody(task)             // desc, sig, tests, constraints
       │
       ├── inlineTypeDefs(task.typeDefs)   // from task (generated by Opus)
       │
       ├── inlineImplSteps(task.implSteps) // from task (generated by Opus)
       │
       ├── computeTokenBudget(all above, contextLength)
       │
       └── resolveCodeContext(task, budget) // whole-file or function-level
              │
              └── if function-level:
                    extractFunctionContext(fileContent, functionName)
```

## Key Implementation Details

### 1. Task Type Extension (`types.ts`)

```typescript
export interface Task {
  // ... existing fields unchanged ...
  typeDefs: string;      // NEW: inlined type definitions
  implSteps: string[];   // NEW: 3-5 implementation steps
}
```

Default values: `typeDefs: ''`, `implSteps: []` — backward compatible with v0.1 tasks.

### 2. Token Budget Calculator (`formatter.ts`)

```typescript
export function computeTokenBudget(
  system: string,
  taskBody: string,
  typeDefs: string,
  implSteps: string,
  contextLength: number,
): TokenBudget
```

Pure function. Returns breakdown. No side effects.

### 3. Code Context Resolver (`formatter.ts`)

```typescript
export function resolveCodeContext(
  task: Task,
  projectDir: string,
  availableTokens: number,
): CodeContext
```

Reads file, checks if whole-file fits in `availableTokens`. If not, calls `extractFunctionContext`. If still doesn't fit, truncates.

### 4. Function-Level Extractor (`context-extractor.ts`)

```typescript
export function extractFunctionContext(
  fileContent: string,
  functionName: string,
  surroundingLines?: number,  // default 5
): { imports: string; targetFunction: string; otherExports: string[] }
```

Regex-based. Finds export boundaries, extracts target function with context. Returns imports separately.

### 5. Updated System Preamble (`formatter.ts`)

Extend `SYSTEM_PREAMBLE` with few-shot example (~400 extra tokens). The example shows a complete small module with imports, types, and one exported function.

### 6. Retry Prompt Redesign (`formatter.ts`)

Replace current `formatRetryPrompt` with version that:
- Always includes full task context (description, signature, typeDefs, implSteps, tests, constraints)
- Always includes latest file content (re-read from disk)
- Varies only framing text and temperature
- Three framings: "fix the error", "rephrased task", "different approach"

### 7. Task Generation Template (`templates.ts`)

Update `buildTasksPrompt` to instruct Opus:
```
Each task MUST include:
- ### Type Definitions: Copy all TypeScript interfaces/types referenced
  in the function signature, tests, or description. Copy verbatim from
  source files. Max ~300 tokens.
- ### Implementation Steps: 3-5 numbered steps describing HOW to implement.
  Include specific function calls, patterns, and logic flow.
```

### 8. Parser Extension (`parser.ts`)

Add to `extractSections()`:
- Parse `### Type Definitions` → `task.typeDefs` (string, preserve formatting)
- Parse `### Implementation Steps` → `task.implSteps` (string array, numbered list items)

### 9. Token Estimation Fix (`formatter.ts`)

Change `estimateTokens`: `Math.ceil(text.length / 3.5)` → `Math.ceil(text.length / 4)`.
