## [Unreleased]

### Added

- **One workspace per run, applied once.** Every writer, retry, validation and code review uses one worktree or staged copy. A passing review makes the result ready to apply. The result menu offers Apply, Show diff and Discard. Apply merges checkout changes into the workspace, checks and re-reviews a changed candidate, then writes with a hash guard and backup. Conflicts halt for per-file resolution; partial writes offer restore or retry. Accept as is keeps open findings and asks once at Apply. Discard and End run preserve `run.patch`. Older runs keep their status and snapshot-ledger behavior. See [Apply](./docs/WORKFLOW.md#apply).

- **The planner consult replaces the hint and intermediate tiers.** When a brief fails after its one local retry, reports `blocked`, or has stale inputs, SPLITBRIEF makes one read-only typed call on the planner's session (`requestConsult`, `src/engine/orchestrator/consult/request.ts`) and acts on the typed `ConsultAnswer` (`src/core/schemas/consult.ts`): `guidance` retries the brief once with the planner's instructions and the context it attached; `rewrite-task` rolls the failed attempt's own files back and replaces the brief at the same id with `revision` +1; `split-task` rolls back and inserts 2–4 subtasks at the next free `T###` ids with `parentId`, re-pointing every pending dependent; `verify` runs the validation pipeline and the named checks through `runChecks` with no implementer call and can complete the brief as `consulted`; `ask-user` is the one question the ladder asks, and its answer continues as guidance. An answer that would drop a criterion becomes that question, and a subtask is never split again. The transcript carries one row per answer (`PLAN → T003: split into T011, T012 · <diagnosis>`), every answer is persisted on the task's lineage and in the session log, and the planner never writes code.
- **The bounds and the grant.** A lineage is bounded at 2 consults and 8 attempts and a run at 10 planner calls after planning (`src/core/pipeline-spec/bounds.ts`; counters in `state.lineages` and `state.plannerCalls`). A spent bound halts with the new `consult-bound-spent` or `planner-calls-spent`, carrying the planner's last diagnosis; `continue` records the operator's note and grants +1 consult and +4 attempts for the lineage, or +5 planner calls for the run, then replays the brief.
- **The stale refresh.** Before a brief is dispatched, the hashes it recorded for its suggested and context files are compared with the workspace; a change runs one restricted (`guidance` or `rewrite-task`) consult with reason `stale`, at most once per revision and without spending a planner call. Guidance records the fresh hashes on the same revision and becomes the first attempt's extra instructions; a rewrite records them on the new one.
- **Seat trouble is bounded before a halt.** A transient seat failure retries the same call up to 3 times with exponential backoff (2s, then 4s, then 8s), and a reported rate-limit reset no more than 10 minutes away is waited for, the deadline persisted as `state.seatWait` (`seat_wait_started`) so a resume keeps waiting. A longer or unreported reset keeps the `runner-usage-limit` halt with the seat picker, and there is no automatic seat switch. The idle watchdog's cut fires only after 20 minutes with no event and no running child process, counts as one attempt, and publishes `no_progress_cut`.
- **The implementer's report is typed.** `ImplementerReport` (`src/core/schemas/consult.ts`) ends the direct writer's reply as one JSON object — `{"status":"done","filesChanged":[…],"touchedNotSuggested":[…],"notes":…}` — and the `file-bundle-v1` grammar gains the blocked form `{"version":1,"blocked":{"question":…,"filesNeeded":[…]}}`. A blocked report starts a consult at once; a missing or invalid report is advisory and changes nothing.
- `runChecks(checkIds)` runs a plan's `test` and `cmd` checks by id through the validation runner and records pass/fail per check; a `render` check reports `not-runnable` until the checks scheduler lands. The state operations `REPLACE_TASK`, `INSERT_TASKS`, `RECORD_CONSULT`, `COUNT_ATTEMPT`, `COUNT_PLANNER_CALL`, `GRANT_ALLOWANCE`, `SET_TASK_INPUT_HASHES`, `RECORD_CHECK_RESULTS`, `SET_SEAT_WAIT` and `CLEAR_SEAT_WAIT` carry it, with no `stateVersion` bump.
- **One planning session with a typed plan.** Every run plans in one session: the planner answers with one typed plan (`PlanAnswerSchema`, through each seat's native JSON-schema flag or the JSON fallback), written to the session folder as `plan.json` and rendered as `plan.md` and `tasks.md`. Before the plan it may ask up to three questions per round, for at most two rounds, each with a default; an empty `⏎` takes the defaults. `checkPlan` and the context fit check the plan deterministically (ids, criteria and checks, dependencies and batches, paths inside the project, implementer context); a plan that fails goes back to the planner once, and a second failure halts with the new `plan-checks-failed` recovery (`plan-questions-exhausted` for a third round of questions). A task gains optional `criteria`, `checks`, `suggestedFiles`, `contextFiles`, `exclusions`, `batch`, `protectedOperations`, `revision` and `inputHashes` with no `stateVersion` bump; each brief carries the fresh code of its read-only context files (40,000 characters per task, cut with `…truncated`).
- **The plan card.** The one approval before the build: Approve plan and start the build, Request changes (the correction goes to the planning session, which answers with a new plan), Edit plan.json (the in-app editor checks the JSON, the schema and `checkPlan` before it saves and shows `Not saved: …` otherwise; `Ctrl+E`, `e` and `edit` open the same file, and `Ctrl+O` settles the card with an external edit), and End run. Approving it confirms the plan's `protectedOperations` in advance, so a listed protected write does not ask again during the build; the panel names them above its rows (`Approving also confirms: write package.json`), so they stay in view while the plan scrolls. A headless run approves the card unattended and confirms nothing.
- A three-stage header rail: Plan, Build, Review.
- Typed seat output: `requestTyped`, in the new engine `typed-output` module, asks any seat for one JSON answer, validated by Zod, with one repair request; claude-code and antigravity get `--json-schema`, codex gets `--output-schema <file>` only for a schema its strict mode accepts and the prompt fallback for any other, the `api` kind gets `response_format: json_schema` (falling back to the JSON prompt when the endpoint rejects it), and every other tool or kind is asked for one final JSON object; a second invalid answer is the new `seat-protocol-error` recovery reason; each CLI tool now records `typedOutput`, native from the release that its `--help` and a live probe proved (claude-code 2.1.287, codex 0.157.1, antigravity 1.2.14) or fallback, and an older release gets the fallback. The planning session uses it.
- `npm run test:e2e:publish`, the one-row pre-publish smoke (`testing/e2e/scenarios/live/publish-smoke.test.ts`): the shipped crew pinned in code — `claude-code` · `opus` plans and reviews, `claude-code` · `sonnet` builds — through the release-matrix harness on the `quick` task, passing only when the artifact validates, `summary.json` is `complete` and `review.md` carries a passing verdict. Its switch is `SPLITBRIEF_PUBLISH_LIVE=1`, which the script sets; unset, the file skips and exits `0`.
- Cursor Agent CLI (`cursor`) is an admitted `kind: cli` tool.
- Command Code (`command-code`) is an admitted `kind: cli` tool.
- `npm run release-check` is the PR gate: `format:check → typecheck → lint → test → test:e2e → check:invariants → skills:check`. `npm run test-ci` remains the exhaustive form that runs the coverage thresholds instead of the plain test run.
- A live end-to-end tier that drives the real CLI binaries (`testing/e2e/scenarios/live` for the easy and heavy scenarios, `testing/e2e/scenarios/real-cli-planner-implementer-smoke.test.ts` for the smoke one, `testing/e2e/vitest.live.config.ts`), opt-in behind `SPLITBRIEF_REAL_CLI_E2E=1` through `npm run test:e2e:live`, `test:e2e:live:heavy`, and `test:e2e:live:smoke`. Nothing in the default `npm test` or `npm run test:e2e` path spends a token.
- A Task Brief is a slice, not a file. Frontmatter takes a `files:` list beside `file:`; `file` stays the anchor and must be a member of the list, and a brief with no `files:` resolves to `[file]`, so every persisted state and every existing brief keeps its behaviour with no `stateVersion` bump. Drift, the commit set, the evidence stamp, the review packet, test narrowing and the implementer prompt read the whole set.
- `src/core/pipeline-spec/` is where the countable rules of the pipeline live: the local retry count, the implementer and reviewer deadlines, the review cycle cap, the halt signatures, the gate table and the allowed commands. The orchestrator imports it and `scripts/sync-skills.ts` renders the generated skill blocks from it, so `npm run skills:check` fails when the two sides drift apart.
- A validation stack registry (`src/core/validation/stacks/`), one row per stack — TypeScript, JavaScript, Python, Go, Rust — carrying its markers, its typecheck, lint and test commands, its test-file patterns, its narrowing kind and its allowed commands. `validation.stack` pins a row; otherwise the row is detected from the repository's own markers. Every stage resolves through `config → manifest script → planner-discovered → stack default → none`, and a repository no row recognises runs `gates: NONE — review-only` instead of falling back to `npm test`.
- `splitbrief continue <id> --action <skip|retry|switch-seat:<tool>[:<model>]|end-run>` answers a pending recovery with no terminal attached: exit code 1 while the run stays blocked, 2 when the value names no recovery action. `end-run` closes the run and stops there rather than re-entering it.
- An `on_halt` hook event, fired when a run stops for recovery, carrying `sessionId`, `taskId`, `reason`, `recommendedAction` and `resumeCommand`; `${event.resumeCommand}` substitutes into a hook's argv like any other event field.
- `--skills <ids>` on `start`, `resume` and `continue` attaches discovered skills to every seat by id. Discovery reads the project roots `.splitbrief/skills`, `.claude/skills`, `.agents/skills`, `.github/skills`, `.commandcode/skills`, `.kilo/skills`, `.kilocode/skills` and `.cursor/skills`, and their global equivalents; what does not fit the 16 000-character budget is named by path, never cut, and a body named that way raises a `skills_truncated` warning.
- Three runtime commands: `/tasks` shows the brief list, `/resume` continues a paused or stopped run, and `/end` closes the run, keeping every change on disk.
- A modal stop sheet. On the workflow screen, `esc` opens `Stop options` with or without a draft: `Stop now` (stop execution, keep partial changes), `Pause after this brief` (finish the running brief including its checks and review, start no next one) and `End run` (stop and close the run), chosen with `↑↓` and `⏎`, no letter keys. No option reverts files and the draft is preserved. `ctrl+c` is Stop now; `ctrl+q` and `/quit` stop, save the session, then exit. A run calls itself paused or ended only once the processes it owns have exited.
- A Build progress block under the header rail while briefs run, at every width: passed briefs of total, the activity line (the seat and what it is doing, or the gate command it is inside), `attempt <a> of <max>`, and either an ETA or the reason there is none. A seat the idle watchdog has warned about is reported as silent instead of as working.
- Antigravity (`agy`) is an admitted `kind: cli` tool; its model list is parsed from the tool's own `agy models`.
- A live fixture end-to-end row, `npm run test:e2e:live:fixture` (`SPLITBRIEF_REAL_CLI_E2E=1` with `SPLITBRIEF_LIVE_FIXTURE=1`), which drives the real CLI binaries through one fixture feature and asserts the run directory, the `--plain` stdout and the working tree. It records a manifest as drift evidence, not as admission proof, and never runs in CI.
- **A run is a durable, continuable record.** One vocabulary says how it stands (`RunStatus`, `src/core/sessions/run-status.ts`): `running`, `open` with a stop reason and the step it picks up at, or `closed` as `complete` or `ended`. `deriveRunStatus` is the only place that decides, from the saved state, the session lockfile and the artifacts on disk; the sessions list, the run screen, the CLI guards and the engine's finalize all read it instead of inferring their own. Two things close a run: passing the final review, and choosing End run.
- `CLOSE_RUN`, `INTERRUPT_STEP` and `RESUME_STEP` on the state machine. `CLOSE_RUN` records `closed: { at, as: 'ended' }` and every later transition over a closed state is refused, except a repeated `CLOSE_RUN`, which returns the state unchanged; `INTERRUPT_STEP` records which step a stop cut and whether the cut landed `mid-step` or at a `boundary`, and `RESUME_STEP` clears it. `state.json` gains three additive optional fields — `closed`, `interruptedStep`, `lastFailure` — with no `stateVersion` bump.
- **One continuation path** (`continueRun`, `src/engine/orchestrator/run/continue.ts`). A park this process holds settles in place, a run at rest is re-entered on its saved state, and a closed run is refused with its reason. What the operator types rides in as a *steer* folded into the step's own prompt rather than replacing it: the planner with a native session gets one extra user turn, a stateless planner gets the rebuilt prompt with the partial and the steer trailing it, the reviewer re-issues its whole deterministic prompt with the note, and a brief restarts on its own prompt with the declared files it already changed named.
- **History replay.** `readRunEvents(ref)` (`src/engine/events/replay.ts`) reads `session.jsonl` back into an `EngineEvent[]`, skipping records whose type or payload no longer parses, and `loadEvents` (`src/stores/workflow/actions/load.ts`) folds the whole log through the live reducers in one commit per store. Opening a run from `/sessions`, from home or from the palette replays its history onto the run screen.
- Five planner-seat recovery reasons — `planner-call-failed`, `planner-returned-no-briefs`, `constitution-check-failed`, `brief-review-no-progress`, `brief-quality-unrepaired` — and two recovery actions, `revise` and `revise-spec`. Every recovery issue now carries the `seat` it belongs to, so the panel and the swap offer name the seat that is actually stuck.
- `wait-attempt.sh` and `splitbrief-gate.sh` under `skills/*/scripts/`: the first waits on an attempt and reconciles a run directory after a crash, with `--deadline` as a loop counter because stock macOS has no coreutils `timeout`; the second reads `progress.md` and refuses to end a skill run while a brief is still pending.

### Changed

- **The ladder is attempt → one retry → consult.** `DEFAULT_LOCAL_RETRIES` is 1 and `workflow.max_retries` is retired (it loads with one notice and is ignored); after the retry the run consults the planner instead of running a fixed tier chain. A task completed off a consult carries the new completion method `consulted`, and the old `escalated-hint`, `escalated-intermediate` and `escalated-full` values and the old `escalate`, `hint_failed` and `task_scope_widened` events stay parseable so a saved `state.json` and `session.jsonl` still load.
- **`workflow.approve` is `plan | none`** (default `plan`). Retired config keys load with one notice each and are ignored: `workflow.mode`, `workflow.task_review`, `workflow.brief_review`, `workflow.speckit` and `approval.tiers`; `workflow.approve: all|spec|default` loads as `plan`. `splitbrief doctor` and the start readiness report list every load-time notice, its **Workflow** section reports the approval level as `approval.resolved`, and readiness checks one context floor (32,000 tokens) for every run.
- **Old runs continue as one planning session.** A run saved before this release that stopped at its spec, plan or briefs gate (or inside the old step chain) continues as one planning session that reads its earlier research, spec, plan and briefs; only the plan card of a run that has `plan.json` re-opens. A saved rewind runs the session with its comment, then opens the card.
- `splitbrief spec` runs the same planning session and writes `plan.json`, `plan.md` and `tasks.md`; in a terminal it prints `The planner asks:` and reads one line, without one it takes every default, and it no longer echoes the planner stream.
- **Scope is guidance, and the implementer implements.** A brief's files are suggestions. A direct-write implementer may edit another ordinary project file the change needs and names it as `Also changed (not suggested): <file> — <reason>`; the CLI implementer gates such a write instead of rejecting it (`undeclaredWrites` defaults to `'gate'`), `write_out_of_scope` is `auto`, and the revert retry (`SCOPE_RULE.revertInstruction`) is gone. SPLITBRIEF records the file as one dim transcript row (`T003 also changed src/x.ts`, the `task_touched_not_suggested` event), as an `info` drift finding (`<file> touched, not suggested by any task.`, which never fails drift) and in the review's Changed Files section, and the test stage runs the tests of every changed file, not only the declared ones. Only a protected path asks: dependency manifests and lockfiles (`package_change`), `.git` and `.splitbrief` (`destructive`), and CI configuration and env or key files (`sensitive_change`, a new class whose prompt reads `Change a CI or secret file:` and keeps `y` on its Confirm row). That confirmation is required whatever `approval.enabled`, `approval.tiers` or `--yolo` say (the `--yolo` transcript row reads `tiered approvals off · protected paths ask`), is asked once, at the write and not again before the brief starts, holds for the same path for the rest of the run, and a denial discards only the denied file and says so; when every write of an attempt is denied, the brief halts with the `approval-denied` recovery. A config that sets `approval.tiers.destructive`, `approval.tiers.package_change` or `approval.tiers.sensitive_change` loads with a notice that the key is ignored, and readiness reads `File-write approval prompts: disabled; protected paths still ask.` A resumed run now restores an unplanned file the interrupted brief promoted, not only its declared files. A confirm gate in a short terminal sheds its blank rows first, so its legend and bottom border stay on screen. The direct-writer preamble and closing line leave the typecheck, lint, format and test gates, the whole suite and render tools to SPLITBRIEF: the implementer runs at most the brief's focused test files, once. The planner prompts stop ordering gates and renders in briefs, a final-review fix may change any ordinary project file, and a `None.` / `n/a` / `-` Scope bullet is no path. Constitution 2.3.0 amends Principle II to match.
- Every overlay key legend fits its width by dropping whole `·`-separated tokens, never half a key. A skill's name takes the whole row when a 60-column terminal hides the skills overlay's description column. The document gate's scroll hint reads `shift+↑↓ scroll · home/end ends`, and no key legend shows above an open stop sheet.
- The `splitbrief-babysit` skill always launches the run in a named tmux session when tmux exists and hands the owner `tmux attach -r -t <session>` to watch it read-only.
- **Briefs are grouped by coherent outcome, not by count.** The brief cap (`ModeSpec.briefCap`), the numeric slice budget (`SLICE_BUDGET`: five files, eight for a frontier implementer, about 200 changed lines) and the count-only mode advice (`MODE_UPGRADE`, the upgrade above five files or five briefs and the stop above twelve) are gone. One rule, `sliceRuleText()` (`src/core/pipeline-spec/brief.ts`), feeds the planner prompt and the portable skills: one brief delivers one reviewable outcome with its tests, wiring and documentation, and only the real model context and prompt transport bound it. A run may hold any number of briefs. The plan checks and the prompt-size refusal stay; historical `mode_advice` events still load.
- **Nothing resets to `idle`.** `idle` is the pre-`START` phase; the phase moves forward and a run ends by being closed. `resetToIdle`, `CANCEL`, `REJECT_SPEC`, `REJECT_PLAN`, `REJECT_BRIEFS`, `CONSTITUTION_CHECK_FAIL`, `ABORT_PENDING_RECOVERY`, `ABORT_TURN` and `CONTINUE_TURN` are gone from the state machine.
- **The plan card never rejects.** It offers Approve · Request changes · Edit · End run; anything else re-opens the card rather than ending the run. The recovery action `abort-workflow` is now `end-run`, and the recovery reason `implementer-timeout-repeated` is `runner-timeout-repeated`.
- **Continuing refuses only a closed run.** `splitbrief resume` and `splitbrief continue` pick up a run parked, waiting at a gate, halted on a decision, stopped by an error or killed outright. The refusals are a missing or unreadable `state.json`, no active pointer, and a closed run. A failure is recorded on the state as `lastFailure` and reported as an open run stopped for reason `failed`, not as a terminal status. The active-session pointer is released when a run closes, not when it stops.
- **One screen for a run, live or not.** The summary screen is gone, and with it the `summary` route, `loadSummaryContext` and `resume-verdict.ts`. A run that stops stays on the run screen at rest — the same header rail, the same transcript, the same footer — and typing a correction flips it back to live in place. A closed run takes `/commands` only and grows a `Closed ─` block at the tail of its own transcript, carrying the outcome sentence, the brief rows, the changed files and the run's facts.
- **Pause after this brief parks the run.** A boundary pause records the brief it stopped before and waits on the composer exactly as a mid-brief park does, instead of ending the run. A host with no prompt surface records the park and returns, resumable at that brief.
- `Session.status` is `open` | `complete` | `ended`, derived rather than taken from the exit path. The legacy literals `interrupted`, `failed` and `cancelled` still parse and map to `open`.
- The Settings panel explains the row under the cursor instead of ending in a block of dim prose. A labelled rule naming the row heads the help, drawn to the panel edge; a bounded number keeps its range on the line that names it, an enum lists its options, and an unset `Test command` reads `auto`. Values are as bright as their labels, the title no longer spends a blank row on the filter, and the gap between sections is spent only where the list has rows to spare, so an 80x24 terminal shows a settings row where it used to show a gap. The legend names the key the row answers to: `space cycle` on an enum, `space toggle` on a boolean. The help block is bottom-anchored in a fixed five rows, so its rule always clears the last list row by a blank one and the legend never moves between rows.
- Crew is no longer a surface of its own: it is the first section of Settings, one labelled row per seat (`PLAN`, `BUILD`, `REVIEW`), and the same rows build the first-run Setup screen. The Settings seat sections that showed the same three facts in a second vocabulary are gone; ready-made crews are offered in Setup only, where choosing one is still a single save.
- Every overlay panel, the home body and the composer take their width from one rule (`overlayRect`, `src/core/navigation/overlay-rect.ts`) with three density classes — `compact`, `roomy`, `wide` — instead of a pinned constant per surface. An 80-column terminal and a 120-column terminal no longer render byte-identical panels, and `OverlayPanel` has no `maxWidth`. The workflow composer, the transcript and the full-bleed `editor` overlay stay full-width.
- Seat identity is produced by one formatter (`src/core/crew/identity.ts`): `Claude Code CLI · Claude Sonnet 4`, ` · ` as the only separator, sanitized before it is measured. Home, Settings, Setup, the picker mirror and the workflow header and sidebar all read it, so role is carried by a label rather than by hue and the home line fits its budget.
- Reasoning effort is chosen with the model in the seat picker and mirrored read-only on every seat row, and it no longer rewires an inherited reviewer as a side effect.
- The tool/model picker routes providers inline instead of opening a 64-column modal, and each route states its auth as a tri-state — authenticated, not authenticated, unknown — with the action that resolves it.
- Model lists are honest. A CLI tool that cannot enumerate its models says so instead of showing an empty column, and Kilo Code's model list is parsed from the tool's own output.
- Models that differ only by reasoning effort, speed, or thinking budget are one row in the tool/model picker instead of one row per combination. The row expands into a tree of one child per axis the family varies along — `effort`, `fast`, `thinking` — and an expanded parent drops its summary chip and keeps the disclosure glyph, because the children spell out what the chip summarized. `space` cycles the axis under the cursor in place, `⏎` confirms the drafted variant from any row of the family — parent or child, so choosing never means walking back up — and a mouse click on an axis row steps it rather than confirming and dismissing the picker, an axis with nowhere left to step staying an ordinary choice. Only a closed set of option tokens peels off an id (`src/features/runners/model-catalog/option-axis.ts`), so a model carrying any other suffix keeps a row of its own.
- The home screen shows the seat block (`src/features/home/components/seat-block.tsx`): one labelled row per seat, replacing the single-line byline.
- The runtime command registry is 23 commands in five categories (Navigate, Crew, Workflow, View, Input & output), no command carrying an alias, and, where a command takes an argument, prefill. `/crew` opens Settings focused on PLAN; `/crew <seat>` opens that seat's picker directly. No row in the palette errors on Enter.
- New commands in that registry: `/diff` shows the run diff, `/run accept|reject` answers the run approval gate, and `/image` attaches and removes images, offered only when the seat's runner can accept them.
- A quota halt's text prompt offers one row per tool the blocked seat can move to — `switch BUILD to OpenCode CLI`, keyed `[w1]`/`[w2]` — instead of one row listing several behind a single key, and the key pressed opens that seat's picker on that tool; on the TUI panel the halt offers a single `Change BUILD tool`, which opens the picker on the first offered tool. Its headline is one line that fits an 80-column panel (`recovery needed · Ollama hit its limit · resets 17:00`), and the reset is spelled by one formatter — local 24-hour clock, dated only when it is not today — on the panel and on the workflow header, which marks the affected seat while the halt is open. A recovery panel too short for its prompt now keeps its headline and every action row instead of scrolling the choices off screen.
- The stderr effort-drop warning (`src/engine/runners/factory-gates.ts`) is kept for headless runs; in the TUI the picker now clears an unsupported effort at save time and says so in the feedback row.
- **Breaking.** `approval.headless` no longer exists, and a run that has a reply channel is now always prompted. The key only ever forced fail-closed on a run that could have asked — a `--json` or `--plain` run with nowhere to send the question already fails closed on its own — so the behaviour it bought is the default, and `ApprovalConfigSchema` is strict, which makes a stale `approval.headless: true` a load error rather than a silently dropped key that would quietly reopen prompting.
- CI is split into four jobs — `static` (format, lint, typecheck, invariants), `unit` sharded four ways, `e2e-replay`, and `smoke` (the TUI screenshot scenario) — instead of one job running `npm run test-ci`, with `concurrency` cancelling superseded runs and push builds limited to `main`. Coverage moved to its own nightly workflow (`.github/workflows/nightly-coverage.yml`, 04:00 UTC plus `workflow_dispatch`), so a coverage threshold no longer blocks a pull request.
- One name per fact on every surface. A model's name is prettified by one formatter (`formatToolModel` and `formatModelName`, `src/core/model-display.ts`), which the summary, the transcript and the workflow activity header all read, so a raw id never reaches a rendered cell. A seat's billing posture is one word from `billingWord` (`src/core/runners/runner-billing.ts`). `PLAN`, `BUILD` and `REVIEW` are the only seat words, from `CREW_SEAT_LABELS` (`src/core/crew/identity.ts`) — on home, Settings ∋ Crew, Setup, the workflow activity header and a closed run's ledger, which gains a `REVIEW` row of its own. An inherited review seat reads as one sentence, `same as planner` (`PLANNER_INHERITANCE`, `src/core/crew/identity.ts`), with `= planner` as its mark.
- An implementer call has 20 minutes and a reviewer call 10 (`TIMEOUTS`), a runner's own `timeout` may not exceed 1 200 000 ms, and two consecutive timeouts halt the run for recovery instead of spending a third attempt.
- A final review that returns `fail` re-enters implementation for the briefs its Critical findings name, re-runs their checks and drift, and reviews again — at most twice. Still failing after that, the run ends with `review: failed`, exit code 1 when headless, and a summary that says so instead of reporting a clean build.
- One matcher decides what a brief may write (`src/core/scope/declared-set.ts`): its `files` plus every path its Scope names under **In bounds** and **Approved out of bounds**. Drift, the CLI exact-effect gate, user-edit classification, chain analysis, tiered approval and context routing all ask that function, so a prose bullet naming a path licenses it in every consumer.
- The baseline exemption compares failure sets, not stage colour. A stage already red before the run exempts an attempt only when the failures after it are a subset of the baseline's; a new failure in a file the brief never touched fails the stage.

## [0.1.0] - 2026-08-07

Initial release — source install; not yet published to npm. SPLITBRIEF was developed in
the open before this date; everything in this section and the dated sections below it is
what 0.1.0 contains.

### Fixed

- The repo map extracts symbols from Python, Go, and Rust again. The grammars came from `tree-sitter-wasms@0.1.13`, whose parsers are built against tree-sitter 0.20 (ABI 13); the pinned `web-tree-sitter@0.26` refuses to load them and `loadGrammar` swallows the failure, so every `.py`, `.go`, and `.rs` file reached the planner with zero symbols and zero imports while 49 MB of unusable wasm shipped to every install. The three languages now resolve their own grammar packages (`tree-sitter-python`, `tree-sitter-go`, `tree-sitter-rust`, ABI 14/15), which are also smaller. Go type declarations carry their name on a nested `type_spec`, so `type User struct{}` was invisible even once the grammar loaded; `extractName` now unwraps it the same way it already unwrapped `lexical_declaration`.
- Readiness no longer headlines an installable blocker with `Required action: Exit`. A missing, untrusted, incompatible, unauthenticated, or unreachable runner is the most common first-run blocker and carried no next action at all, so `selectNextAction` fell through to `exit` — or, when a repository blocker was also present, to `Clean or isolate repo`, which named the wrong problem. Runner blockers now carry `prepare-runner` (`Set up the configured runner`).
- The start gate names the tool and its install URL when a CLI is missing. `Fresh CLI evidence denied admission: installation.` previously fell back to the generic `Review the configured runner, then retry.` even though the catalog already holds an `installUrl` for every tool.
- `node-pty` moved from `optionalDependencies` to `devDependencies`. Only `testing/` imports it, but it was downloaded and its native install script run on every `npm install -g splitbrief` — 62 MB, and a `node-gyp` fallback on Linux, for a module no shipped file can reach.

- A cloned repository can no longer grant itself hook execution. The hook trust receipt moved out of the project (`.splitbrief/hook-trust.json`) into the owner's machine-scoped store (`~/.splitbrief/trust/hooks.json`, mode `0600` in a `0700` directory), keyed by the canonical path of the checkout — the same store, identity, and owner-only read that custom runner trust already used, now shared through `src/core/trust/receipt-store.ts`. A receipt committed into a repository is a file SPLITBRIEF never reads; a second clone, a `cp -a`, or another account prompts again. Receipts written by earlier versions inside `.splitbrief/` are ignored: trust those hooks once more and delete the file.
- The hook trust prompt now discloses what it authorizes, and cannot be answered without it. The question itself carries each hook's executable, the absolute path that executable resolves to on this machine, its argv, and the trust boundary the hook runs inside, so every surface that answers the prompt must display it. A config-supplied `name:` no longer displaces the command in the disclosure, and repository-supplied strings are rendered as escaped literals so bidi or zero-width characters cannot redress one command as another. `--allow-hooks` writes the same disclosure to stderr before granting, so CI logs record what was authorized.
- Multi-line trust disclosures no longer collapse into one run-on line in the TUI approval prompt; the line breaks survive sanitization and the prompt's row math counts them.
- Readiness no longer certifies a CLI runner as authenticated because the sandbox roots are non-empty. The probe's credential-presence fact now asserts that the bridge's own destination file exists for that tool and channel, so the files a probe writes into the staged HOME — Claude Code drops `.claude.json` and a backup during a readiness run — are no longer read back as proof of a credential. A credential the staged child cannot read is a credential it does not have.
- The Claude Code subscription `session` channel works on macOS, where the credential is a login-keychain item the file bridge cannot carry. An auth channel now declares `hostKeychainPlatforms`, and a channel that resolves to `host-account` there keeps the host `HOME` and `USER` — the two values the keychain's search list and item account are keyed on — while `TMPDIR`, `XDG_*`, `npm_config_cache`, `PIP_CACHE_DIR` and `CARGO_HOME` stay redirected into `.splitbrief/sandbox/` and nothing is copied to disk. `session` is the default on every platform again, so a fresh macOS config no longer bills per token for a subscription the user already pays for. The security cost of that one channel — `~`-relative reads and Claude Code's own state writes land in the real home, and the login keychain resolves by default — is stated in `docs/WORKTREES.md`, `docs/API-KEYS.md` and `docs/HOW-IT-WORKS.md`. No other tool, channel or platform changed.
- Readiness never infers a keychain-backed login from directory contents. Where the staged environment cannot observe a credential it says so and runs the tool's own status command; `claude auth status` reporting `"loggedIn": false` is still `unauthenticated`, with `Sign in to claude-code on this host` as the fix.
- Readiness and the start gate name the credential that is missing and the command that supplies it (`Export ANTHROPIC_API_KEY …`) instead of `Authenticate claude-code in the staged runner environment` / `Review the configured runner, then retry.`
- The detection cache no longer rejects its own context key when a runner uses the `api-key` channel: the key names the channel, and the literal `api-key` tripped the credential-material heuristic, silently disabling caching for that runner.
- Every command now canonicalizes the project directory to the git toplevel, not only `start`. Run from `packages/web`, `doctor` no longer reports `config.missing`, `ps`/`status`/`last`/`resume`/`stats` no longer report an empty project, and `spec` no longer auto-creates a second `.splitbrief/config.yaml` plus a `.gitignore` inside the package directory. An explicit `--project` pointing inside a repository still prints the relocation warning; a bare subdirectory invocation relocates silently.
- A mistyped subcommand no longer starts a workflow named after the typo. A single bare operand that is not a registered command but is one edit from a short command name or two from a longer one (transposition counted as one edit) is rejected with `unknown command 'doctro' — did you mean 'doctor'?` and exit `1`. The bare-feature shorthand is untouched: `splitbrief "fix the typo"`, `splitbrief fix the typo`, and `splitbrief start doctro` all still run.
- `engines.node` is enforced at runtime. The CLI reads `process.versions.node` before parsing and refuses a Node older than 22 with `splitbrief requires Node.js 22 or newer; this process is Node.js <version>.`, instead of running and reporting a wrong diagnosis — on Node 20 the arg-vector preflight truncates its `--help` capture and blocks on flags the installed binary does support.
- Documented `kind: api` examples now load. `service` and `offering` were missing from the examples in CONFIGURATION.md, CONCEPTS.md, FEATURES.md and IMPLEMENTER-DIRECTION.md while the field table promised a catalog back-fill that has never existed, and the generic remote example taught `apiKey: env:VAR` — the one credential form a custom provider is refused. Every YAML fence in `README.md` and `docs/*.md` that names a top-level config key is now loaded through the real `loadConfig` by `testing/docs/configuration.test.ts`, whole configs as written and section fragments under a `version: 3` header, and every documented `kind: api` block is checked for the identity triple it cannot be inferred from.
- `docs/GETTING-STARTED.md` §8 no longer documents an always-visible `spent … proj … budget … cache …` status line that nothing renders. It describes the four surfaces that exist — the `/sidebar` footer, the Ctrl+G breakdown, the summary screen, and the budget gate — and `testing/docs/getting-started.test.ts` checks each name against the registry or threshold constant that produces it.
- A Task Brief quality failure is no longer a dead end for headless, RPC, or any other auto-approving transport. Those transports answer every approval with "approved", and the quality gate is deterministic over unchanged briefs, so a standard-mode run whose planner split each implementation and its test into separate briefs — leaving the implementation brief's `### Tests` section as prose — re-approved the same rejected briefs twenty times in about fifty milliseconds, emitted twenty identical error records, and ended as `interrupted`. The briefs approval loop now spends one automatic planner regeneration with the blocking issues as feedback, and rejects immediately with a `brief_quality_rejected` error naming every issue if the regenerated briefs still fail. An edited `tasks.md` that fails the gate is still reported and re-prompted, never overwritten. The Task Brief prompt also states what the contract always meant: a brief whose test file a sibling brief owns still lists the concrete cases that verify its own change.
- A first run on a machine with no Ollama no longer prints `detectContextLength(ollama): fetch failed` to stderr before the UI appears. An unreachable provider endpoint is handled by falling back to the catalog, exactly as `fetchModelList` already treated it; readiness is where an unreachable implementer is reported. Diagnostics that are not connection failures still print, now credential-redacted.

### Added

- The final review is now its own seat. An optional top-level `reviewer:` block in `.splitbrief/config.yaml` — the same discriminated union as `planner:`, the same five kinds, the same generation fields, no `version` bump — names the runner that reads the run diff. Leave it out and nothing changes: the planner holds the seat, review tokens are priced at the planner's rates and folded into the planner line, and an existing config loads without edits or warnings. Set it and the diff is read by a model from a different lab than the one that wrote it, priced on its own line. Only the final review moves. Planning, Task Brief compilation, escalation, the planner estimate review, summarization and brief recovery stay on the planner. A configured reviewer is admitted at start like every other seat, so one that cannot run blocks the run instead of being skipped; one that fails mid-call is reported as a failed review with its own identity in the error, and the review is never quietly re-run on the planner. Nine `--reviewer-*` flags mirror the planner set on `start`, `resume`, `continue`, and `last`; `/reviewer` opens the picker.
- `/crew` — one surface showing every seat of the run at once: `PLAN`, `BUILD` with its `escalate` branch, `REVIEW`, each with tool, resolved model, and billing posture, and a line saying whether the review comes from a different lab than the build. Enter on a seat opens that seat's picker and returns with the seat changed. Ready-made crews are offered when every tool they need is installed and authenticated, and applying one writes all three seats in a single save. First run now opens this instead of the two-step wizard, and continues to the same place the wizard did. **Superseded in `[Unreleased]`** — the standalone overlay is gone (crew is the first section of Settings), and the `escalate` branch was removed with the escalation picker; the escalation tier itself is retired and the planner's consult replaces it.
- `splitbrief init --yes` writes the default config without the interactive picker, and `splitbrief init --project <dir>` targets a directory. Without a TTY, `init` previously refused with `use --json or --detach` — two flags it has never accepted — leaving CI, container builds and piped shells with no documented way to create a config.

### Changed

- Headless `--json` runs now exit non-zero for a **paused** or **applying** `pendingRecovery`, not only `awaiting-user` — a resume that does nothing no longer exits 0. The `recovery_required` record carries the `status` field (optional for older consumers), and the task loop publishes a transcript-safe `recovery_pending_unresolved` warning naming the reason, status, and available actions before stopping.

- `splitbrief resume` now correctly handles `awaitingContinue` state.

## 2026-04-20 — EventBus architecture

Unified `EventBus` replaces every per-call-site callback. The workflow hook
system, repo-map planner context, OpenTelemetry integration, and a headless
`--json` mode all ride on top of the same bus. Design rationale is folded into
the subsystem docs (`ARCHITECTURE.md`, `HOOKS-CONFIG.md`, `REPOMAP.md`,
`OTEL.md`) rather than kept in separate ADRs.

### Added

- **EventBus** — single typed `EngineEvent` discriminated union (50 variants); engine emits via `bus.publish()` and UI/persistence/hooks subscribe as sinks. Replaces ad-hoc `callbacks.onEvent` + direct `appendEvent` calls. ([ARCHITECTURE.md §Design decisions](docs/ARCHITECTURE.md))
- **Hook system** — 11 workflow lifecycle hooks (`pre_task`, `post_commit`, etc.). Shell-spawned commands (`kind: "command"`) and in-process JS modules (`kind: "module"`). Trust prompt + `--allow-hooks` flag for CI. 2 built-ins: `prettier-on-change`, `block-secrets`. ([HOOKS-CONFIG.md](docs/HOOKS-CONFIG.md))
- **Repo-map context** — Aider-style codebase symbol summary auto-injected into the planner. Tree-sitter parsing, PageRank ranking, SQLite cache. ([REPOMAP.md](docs/REPOMAP.md))
- **Headless `--json` mode** — `splitbrief start --json "..."` and `splitbrief resume --json` emit each EngineEvent as NDJSON to stdout. TUI render skipped. Auto-approves workflow review gates; file-write sticky/confirm approvals fail closed unless configured or granted.
- **OpenTelemetry sink** — opt-in (`otel.enabled: true`) span emission for workflow lifecycle, phases, and tasks. Per-cost attributes. Users register their own exporter. (`docs/OTEL.md`, since removed)
- **`/repomap rebuild`** slash command — clears the SQLite cache.
- **`pre_planning` hooks** — fire before planner phases.

### Changed

- `OrchestratorCallbacks.onEvent` removed. Engine no longer accepts inline event callbacks; subscribe to the bus instead.
- `Planner.plan()` and `Planner.quickPlan()` signatures gain optional `codebaseContext?: string` parameter.
- Validator pipeline (`tsc → lint → test`) now fires `pre_validation` / `post_validation` hooks.
- Per-task git commit fires `pre_commit` (can deny) / `post_commit` (informational) hooks.
- Config schema (`.splitbrief/config.yaml`) now supports optional `hooks`, `codebase`, `otel` top-level blocks.

### Removed

- `OrchestratorEvent`, `OrchestratorEventPayloadMap`, `SessionLogEventEntryFor` legacy types (superseded by `EngineEvent`).
- Legacy `appendEvent` (use `appendEngineEvent` instead).
- `TuiEvent` and the `engine→features` bridge sink (renderers now consume `EngineEvent` directly).
- `OrchestratorCallbacks.onEvent` field.

### Architecture

- 0 `engine → features` imports (was the layer violation rationale for the whole 2026-04-20 release).
- 7 grep gates enforced pre-merge: `callbacks.onEvent`, `OrchestratorEvent`, `from features in engine`, `throw new Error in engine`, barrel `index.ts`, `TuiEvent`, `features/workflow/types`. All return 0.
- Full test suite green; typecheck and lint clean.

### Amendments beyond original plan

- **OpenTelemetry sink** — added as the third EventBus sink (opt-in via `config.otel.enabled`). Span hierarchy: `splitbrief.workflow` → `splitbrief.phase.<name>` → `splitbrief.task`. Bring-your-own `TracerProvider`; a console-exporter shortcut is available via `SPLITBRIEF_OTEL_EXPORTER=console` or `--otel-exporter console` for local debugging. (`src/core/schemas/otel.ts`, `src/engine/events/sinks/otel.ts`)
- **Headless mode (`--json`)** — no-TUI execution, NDJSON `EngineEvent` stream on stdout, review-gate auto-approval, empty clarification answers, fail-closed tiered approvals unless configured or granted. Pairs with `--allow-hooks` for non-interactive CI. (`src/cli/headless.ts`, `src/engine/events/sinks/stdout-json.ts`)
- **tuiSink redesign** — because `TuiEvent` and `src/features/workflow/types.ts` were deleted outright, the planned `EngineEvent → TuiEvent` mapper became vestigial. `createTuiSink()` is now a thin pass-through that returns `actions.addEvent`; the workflow store consumes `EngineEvent` directly. (`src/features/workflow/tui-sink.ts`)
- **Test suite cleanup** — a follow-up audit against `docs/TESTING.md` turned up tests that verified implementation details rather than behavior (sibling `vi.mock('./...')` calls, `toHaveBeenCalled` spies on private helpers, sharded store tests, trivial wrapper hook tests). All were rewritten in behavior style or deleted.

### Migration notes

Existing `.splitbrief/config.yaml` files work unchanged — all new top-level blocks (`hooks`, `codebase`, `otel`) are optional. See [`docs/MIGRATION.md`](docs/MIGRATION.md) for the full 2026-04-20 breaking-change reference.

## Earlier migrations

### models.dev as primary catalog

SPLITBRIEF treats [models.dev](https://models.dev) as the primary model catalog and pricing source. README §Models documents the user-facing contract; the notes below capture the behavior details that used to live in a standalone migration doc.

**Precedence** (first hit wins):

1. `models.dev`
2. Runtime provider detection / CLI discovery
3. Bundled offline fallback manifest

**Behavior:**

- CLI tools and subscriptions stay unpriced. We no longer proxy-price `claude-code`, `codex`, `copilot`, `opencode`, `kilo-code`, or `aider` through upstream APIs.
- Claude Code uses tool-native aliases: `auto`, `sonnet`, `opus`, `opusplan`. **Superseded in 0.1.0** — `auto` is no longer a model ID; automatic selection is expressed by omitting `model`.
- Legacy stored `claude-code: default` still works and normalizes to `auto`. **Superseded in 0.1.0** — it normalizes to the omission instead.
- `opencode` and `kilo-code` should usually stay on `auto`; configure the real model in the tool itself. **Superseded in 0.1.0** — leave `model` unset instead.
- `models.dev` prices are already expressed in USD per 1M tokens. Do not multiply them again.
